# Code of conduct

## The short version

Be decent. Argue with the work, not the person. Assume the other party is competent
and acting in good faith until you have real evidence otherwise — and if you have
it, report it rather than litigating in a thread.

## Standards

Behaviour that helps:

- Critique that names the specific claim it disputes and what would change your mind.
- Saying "I was wrong" plainly, and moving on without ceremony.
- Asking what a design decision was weighed against before proposing it be reversed.
  This repository writes its rejected alternatives down; read them first.
- Patience with newcomers to a genuinely dense domain. "Regulated document
  adjudication" is not common background, and neither is defeasible reasoning.

Behaviour that does not:

- Personal attacks, harassment, or sustained disruption.
- Sexualized language or imagery, and unwelcome attention of any kind.
- Publishing others' private information without explicit permission.
- Dismissing a report of any of the above as oversensitivity.

## Scope

This applies in every project space — issues, pull requests, discussions, commit
messages, and any place someone is representing the project — and to conduct outside
those spaces that has a direct effect inside them.

## Enforcement

Report to **kushan.patel@gmail.com**. Reports are handled confidentially. Be honest
about the limits: this is a single-maintainer project, so the person reading your
report is the same person who maintains the code, and there is no independent
committee. If the report concerns the maintainer, GitHub's own
[abuse reporting](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)
is the escalation path that does not run through him.

Consequences scale with the conduct: a private correction, a public one, a temporary
block, or a permanent ban. The maintainer will say which is being applied and why.
